## タスク

`.claude/rules/` 配下のルールファイルを、コードベースの現状に合わせて更新してください。

## 対象ファイル

以下のルールファイルを確認・更新してください：

| ファイル       | 内容                           | 更新時の確認ポイント                          |
| -------------- | ------------------------------ | --------------------------------------------- |
| `product.md`   | プロダクト概要、機能一覧       | Info.plist、AppDelegate、主要機能の追加・削除 |
| `structure.md` | ディレクトリ構成、ファイル一覧 | ファイルの追加・削除・リネーム                |
| `tech.md`      | 技術スタック、ビルドコマンド   | 依存関係、ビルド設定、CI設定の変更            |
| `git.md`       | Git規約                        | 基本的に変更不要（規約が変わった場合のみ）    |
| `behavior.md`  | 行動規約                       | 基本的に変更不要（規約が変わった場合のみ）    |

## 更新手順

1. **現状調査**: コードベースの実際のファイル構成、使用技術、機能を確認する
2. **差分検出**: 各ルールファイルの記載内容と実際のコードベースを比較する
3. **更新実行**: 差分がある箇所のみを更新する（不要な変更はしない）
4. **CLAUDE.md同期**: ルールファイルの変更に伴い `CLAUDE.md` のクイックリファレンスも更新が必要な場合は更新する
5. **結果報告**: 何を更新したか（または更新不要だったか）を簡潔に報告する

## 調査対象

- `cmd-eikana/` 配下の全Swiftファイル
- `cmd-eikana-helper/` 配下の全ファイル
- `cmd-eikanaTests/` 配下の全テストファイル
- `⌘英かな.xcodeproj/` のプロジェクト設定
- `.github/workflows/` のCI設定
- `.swiftlint.yml`
- `Info.plist` ファイル

## ルール

- 事実に基づいて更新すること（推測で情報を追加しない）
- ファイル一覧は実際に存在するファイルのみ記載する
- 既存の記述スタイル・フォーマットを維持する
- `git.md` と `behavior.md` は規約ファイルなので、コードベースの変更では通常更新不要
